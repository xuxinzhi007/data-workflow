# Quality Gate（质量门禁）

编码完成不等于可以提交。本技能用命令的真实输出证明改动质量。改动审核先判断会不会出事，本技能在审核通过之后跑。规范对照在 `../change-review/references/standards-spec.md`。

**分工**：本技能只管编译、单测、覆盖率、生成物一致性。接口契约（进程内契约测试、破坏性 diff、场景回放）归 `../interface-test/SKILL.md`，四态裁决也只在那边出。本技能 G4 发现 Breaking 时**移交**给它，不自己下 PASS/FAIL。

## 何时执行

- 改动审核结论为可继续之后
- 审核指出的问题改完，并再次审核通过之后
- 提交前，作为最终闸门，必须全绿

## 命令从哪来

G1–G5 执行**当前 profile / 该仓库自己声明的 verify·test·build 入口**里的命令列表，不在本文件硬编码某一语言的构建命令。

| 情形 | 做法 |
|---|---|
| `stack: go`（或已加载 go-kratos profile） | 命令表见 `../../profiles/go-kratos/profile.md` 的「质量门禁命令」 |
| 其他栈 / 无 Go profile | 用该仓库声明的 `verify`、测试或构建入口（思路见 `../../workflows/change.md` 的 `done`：verify / package.json / Makefile / pytest / cargo 等已写明的那条） |
| 仓库没有任何可执行入口 | 报告写 `UNVERIFIED`，**不许假装跑过**某一语言的默认命令 |

## 检查项（按序执行）

### G0 圈定改动范围（先做，一切检查锚定它）

按 `../../references/diff-scope.md` 圈定改动文件与符号清单。`next` 会把该文件作为 READS 同屏打出。后续 G1–G6 只针对这份清单，禁止扩大到全项目。嵌入/加载进逻辑的配置算逻辑改动，不得跳过 G2/G3。

### G1 编译与格式

- 按当前 profile / 仓库入口执行编译（或等价）命令，必须通过。
- 依赖注入、格式化检查：只对 G0 清单里相关文件执行 profile 列出的命令；输出必须为空或通过。
- 无可用入口 → `UNVERIFIED`，不假装。

### G2 单元测试（只跑受影响范围）

- 只跑：G0 清单涉及的包/模块 + G4 判定的直接受影响包，按 profile / 仓库入口逐包（或等价粒度）执行。
- 禁止无必要的全量模式；禁止「顺手跑一下其他包」。
- 只改契约/配置/SQL 且无逻辑变化的，跳过并在报告标注理由（嵌入类配置除外，见 G0 / diff-scope）。
- 配置类文件（JSON/YAML）改动：只验证 diff 里的改动条目，不重验全文件、不做全树 dump。

### G3 覆盖率

- 新增导出函数/方法：按 profile 的覆盖率命令证明触达，或存在用例名直接对应。
- 改动的业务分支：必须有断言触达；覆盖不到的写明原因（如外部依赖），不允许默认跳过。
- 门线是「新代码有测试触达、改动文件既有测试保持通过」，不设全项目绝对覆盖率指标。
- 仓库无覆盖率入口 → 该项 `UNVERIFIED` 或跳过并写理由。

### G4 影响验证（会不会影响别处）

1. 列出 G0 清单里改动的符号：函数、方法、结构体、契约字段、配置项。
2. 检索每个符号的调用方。**收敛规则：只对直接调用方所在包/模块跑回归**（命令来自 profile / 仓库入口）；二级传导只列出、标注风险，不跑测试。调用方横跨 3 个以上包时，先用读代码判断哪些包行为真受影响，只跑行为受影响的包。
3. 回归失败 = 影响真实发生，必须修复或回滚。不允许「这个失败与本次无关」式带过——除非能证明失败在改动前就存在。
4. 签名、返回值、行为语义、契约字段号发生变化 → 标记 Breaking Change，移交 `../interface-test/SKILL.md` 跑契约门出裁决，同时停下来向用户报告影响清单，拍板前不进入提交。

### G5 生成文件一致性

- 契约/IDL 有改动：必须按 profile / 仓库入口重新生成；git diff 中生成物的改动只能来自生成。
- 发现手改生成物的一律打回重做。
- 仓库无生成步骤 → 跳过并标注。

### G6 复用门禁

- 含逻辑代码改动时：若当前 stack 有成文的复用门禁（Go 见 `../implementation/references/reuse-gate.md`），执行之。无成文约束则跳过，不自造规则。

### G7 知识反哺（代码动了，域文档跟着动）

只用 G0 的改动清单作输入，不额外跑全库扫描。

**找到这次碰到的域**：

```bash
bash "$PLUGIN_ROOT/scripts/knowledge_drift.sh"      # 已有：打出每份域文档的 FRESH / STALE
```

对每份 `docs/domain/<域>.md`，拿它 frontmatter 的 `watches` 与 G0 清单求交。交集为空就跳过这一步。

**交集不为空时，按条目类型分两半，两类动作不同**：

| 条目 | 例子 | 动作 |
|---|---|---|
| **指针类**（可自动写） | §2 对象与身份、§4 写入口 `文件:符号`、§5 可见性、§6 角色表、`watches` 本身 | 代码改了就直接改成新值，并刷新 `verified_commit` / `verified_at` |
| **口径类**（只标冲突，不改结论） | §1 这一域负责什么、§3 状态族语义、§8 待确认 | 写进 §8「已知冲突」：新旧说法、依据的 `文件:符号`、以哪份为准未定 |

禁止事项，做到就当作这一步没过：

- **不许用代码现状改 §3 的业务口径**。代码证明的是现在会怎么做，不是业务要求永远如此。自动改这一栏等于让代码给自己发合规证明。
- 不许因为这次顺手看到了无关问题就改别的域。
- 不许在没有 G0 证据时丢文档。

**写完后收尾**：

- 指针类都同步上了、口径无冲突 → 刷新 `verified_commit` 为当前 HEAD，记一行到 §9 变更记录，报告标 `✓`。
- 有口径冲突 → 报告标 `⚠ 冲突 N 处`，并把这一条写进下一步（由 `next` 打 `OPEN` 等人拍板）。不自行决定以哪份为准。
- 这次没碰到任何域 → `— 无命中域`，不创建空文档。

## 输出格式

判定三态与四要素按 `../../references/acceptance.md`：每条 ✓ 后面跟命令、**点名的用例**、**期望关键输出**。环境没起导致用例没跑到被测逻辑时，判 `没验成`，不许写 ✓。

```
质量门禁报告
G0 改动范围   改动文件数与分类
G1 编译与格式   ✓ / ✗ / UNVERIFIED（原因）
G2 单元测试     ✓ 通过范围 / ✗ 失败项 / 跳过（理由）/ UNVERIFIED
G3 覆盖率       ✓ 新增函数触达情况 / ✗ 未触达清单 / UNVERIFIED
G4 影响验证     ✓ 回归通过范围 / ✗ 受影响调用方 / ⚠ Breaking 清单
G5 生成文件     ✓ / 跳过（无契约改动）/ UNVERIFIED
G6 复用门禁     ✓ / ✗ / 跳过（无成文约束）
G7 知识反哺     ✓ 刷新了哪几份域文档 / ⚠ 口径冲突 N 处（待拍板）/ — 无命中域
结论：全部通过，允许提交 / 未通过，先修复 Gx / 有 UNVERIFIED 须写明
```

报告落盘 `specs/<feature>/quality.md`（工件树见 `../../references/artifact-tree.md`）。**每条 ✓ 后面必须跟命令与其真实输出摘要**；没有输出的 ✓ 视为未跑，文档审计门会打回。

## 命令纪律（减少人工确认）

- 检索、读文件、找调用方：优先用内建工具（Read/Grep/Glob），不用 Bash 的 cat/grep/管道——内建工具不触发权限确认。
- 验证命令：只用 profile / 仓库声明的现成命令；不现场发明验证脚本。工程约束文件的落点按 `../../references/project-index.md` 解析（`.cursor/rules/` → `.qoder/rules/` → `AGENTS.md` → `CLAUDE.md`），不要把某一个 IDE 的目录名当成事实。
- 禁止重定向、`tee`、管道拼接命令（`>`、`>>`、`|`）——这是触发权限确认的直接元凶；需要看输出就直接读终端输出。
- 必须用自造命令时（项目命令覆盖不了），先用一句话向用户说明要跑什么、为什么，再执行。

## 原则

- 一切以命令真实输出为准，禁止「应该没问题」式断言；没跑过的检查项不许标 ✓。
- **`exit 0` 是通过的下界，不是充分条件。** 它证明命令跑完且成功，不证明验的是这次改的东西。验收四要素与三态判定见 `../../references/acceptance.md`。
- 检查范围锚定 G0 清单：验证密度随改动范围缩放，小改动小跑，不因「顺便」扩大验证面。
- 失败项修复后重跑失败项；若修复涉及逻辑代码变动，从 G1 整链重跑。
- Breaking Change 永远停下来问人，不静默带过。

## 常见错法

- **把 `exit 0` 写成「验收通过」。** 它是下界。还要说验的是哪个用例、对应哪条验收条件。
- **环境没起、用例根本没跑到被测逻辑，却判通过。** 这种情况判「没验成」。
- **失败项修完只重跑那一项。** 修复涉及代码变动就要从整链重跑。
- **Breaking Change 静默带过。** 永远停下来问人。
- **非 Go 仓库照抄 `go build` / `test-unit.sh`。** 没有入口就写 UNVERIFIED，不假装。
