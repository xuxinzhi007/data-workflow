# 定界规则的走查

这是对照 `references/scope.md` 的纸面走查，不是在 data-service 里让代理改过代码。没有需求理解偏差、无关 diff、返工次数或耗时的实测数字。

## 三个例子

1. 「列表上再加一个已有字段的筛选。」现有查询函数已经按该字段过滤。不改 proto。级别 L1，走 `change`，`decision.md` 写复用的 `文件:符号`。不写 ADR，不进九步。旁边模块命名不统一写在「不做」里。
2. 「做一个统一配置中心。」追问后，真正的问题是某一处开关和另一处不一致。最小方案是改那一处现有配置。配置中心写进「不做」，除非写得出更小方案为什么不够。
3. 「加一个状态值。」看起来一行枚举。它落在状态机上，级别 L3，走 `feature` 或 `hotfix`。没有 `plan pass` 和 `passes.log` 时，钩子仍拒绝写 `internal/biz/status.go`。就算有人 `start change`，写保护不看工作流名字。

## 验收对照

| # | 规则上 | 还没证明的 |
|---|---|---|
| 1 简单需求不被强制升级 | `feature.json` 不再把「做个功能 / 加筛选」直接收进九步。L1 指向 `change` | 代理会不会仍自己打开九步 |
| 2 用户给出过重实现时先问目标 | `scope.md` 写明用户的实现方式不是目标 | 没有真实对话记录 |
| 3 无关债不扩大 diff | 三类债里「无关」不进 diff。`check.md` 要核对范围 | 没有 diff 核对的自动检查 |
| 4 相关债要写后果 | 挡住这次的债要比较修与不修 | 同上，靠阶段文件 |
| 5 小改动碰权限或状态要升级 | 文档要求改走 feature/hotfix。钩子不看 `start` 的名字，受保护路径仍要放行记录 | 运行器不会因为 diff 内容把 `change` 改成 `feature` |
| 6 只问关键问题 | 说不清时只问会影响方案的那一句，然后 `wait` | 没有真实对话 |
| 7 完成时对照验收和 diff | `change.md` 第 3 步要求写验收是否达到、diff 是否超出。退出码仍只是下界 | 没有自动 diff 对账 |
| 8 原有门禁没被削弱 | 未改 `workflow_next.py` 和 `gate-edit` | 钩子的 shell 盲区和 `specs/` 可自写放行记录仍在 |
