# confess：把自评从主产物里拆出来

核对日期：2026-12-01。依据：OpenAI《自白技术如何让语言模型保持诚实》（2025-12-03，
<https://openai.com/index/how-confessions-can-keep-language-models-honest/>）。

## 为什么改

现在 `self_check` 是一个字段干两件事：

1. **提示**：告诉 AI 这一步该注意什么（"gate_check 检查工作树真的动过"）。
2. **自评**：让 AI 声明自己做对了（"只改决定里写了的范围"）。

第 1 件必须留。第 2 件是整个体系里最弱的一环，而且**弱的原因不是提示没送到**：

- AI 在写 `decision.md` / `check.md` 的同一次输出里自评。主产物会被人看、要显得完整，
  自评要诚实说缺什么——两个目标挤在同一份文字里。
- `requires` 是字面量门（已证实 V2：`workflow_next.py:353` 全文子串匹配）。写全六行就过门，
  写得好不好没人管。于是"诚实自评"的最优策略是**把六行写漂亮**，不是**承认这里没想清**。
- 诚实有成本：AI 写"这里我没把握"，可能触发 `wait` 停住流程。有成本时模型会选不诚实。

OpenAI 的机制不是"教模型诚实"，而是**给诚实单独开一条通道，且这条通道不参与主奖励的竞争**。
它的实验里主回复的真实准确率在下降、自白的准确率在上升——因为模型发现
"优化自白奖励的最优策略是在操纵主奖励的同时如实承认"。

## 对应到这里

| OpenAI | 这里 |
|---|---|
| 主回复（多维评估） | `decision.md` / `check.md`（人看、`requires` 判、`gate_check` 判） |
| 自白（只评诚实度） | `confess/<stage-id>.md`（只进日志，不入任何门） |
| 独立奖励模型 | 不进 runner 判定。只记录，供事后对照 |
| 自白不惩罚主回复 | **confess 写什么都不会让 runner 打 GATE、不会改变 stage 推进** |

## 硬约束（这几条错了，机制就退化成又一层格式要求）

1. **confess 不参与任何门。** 不检查字面量、不检查长度、不检查有无"待拍板"。
   它甚至可以是"没有可坦白的"。唯一要求是文件存在或 runner 记录了"没写"。
2. **confess 里的内容不改变 stage 推进。** `done` 不会因为 confess 说了坏话而停在原地。
   这是全部要点：**诚实不付代价，才有诚实。**
3. **confess 在 `done` 之后问，不在同一次输出里写。** 顺序是：改完 → `done`（过门、跑 verify）
   → runner 打印 `CONFESS` → AI 单独写 `specs/<feature>/confess/<stage-id>.md`。
   独立的一次输出，不是主产物的续写。
4. **三个问题固定，且是"事实性对账"不是"自我评价"。** 不问"你觉得做得好吗"——
   那是在要一句好话。要问能对得上账的东西：

   1. 我刚才有没有做「{这一步的产物}」里没写的事？
   2. 我说的"验过了"，验的是哪个具体用例、期望什么输出、实际看到什么？对不上就说对不上。
   3. 有没有我编了一个看起来合理，但从没查证过的路径 / 字段名 / 事实？

   第 1 题的花括号按 workflow 取（`workflow_next.SCOPE_ARTIFACT`）：`change` 是
   `decision.md`，`bugfix` 是「根因定位」，`hotfix` 是「止血决策」，`feature` 是方案产物。
   **不能硬写 `decision.md`**——另外三个 workflow 没有这个文件，写错了 AI 会去找一个
   不存在的文件，比不写更糟。锁在 `case_confess_scope_follows_workflow`。

   Python 版的 OpenAI 报告里"自白"的内容正是：目标清单 / 逐条是否真的达到 / 遇到的不确定与艰难抉择。

## 放在哪一步

`change` 现在三步：写下决定 → 按决定改 → 核对。

**不改 stage 数量。** confess 不是第四个阶段，它是每个 `code: true` 阶段（以及第 3 步核对）
`done` 之后的一次独立追问。理由：

- 加一个 stage 会让它变成流程的一部分，又有了"过门"的压力——正好违背第 2 条。
- 它没有产物要"完成"，只有一次记录。

触发点：`cmd_done` 推进成功后。已有 `record_evidence` 在同一位置写 `evidence.log`，
confess 复用同一个时机，但写不同文件，且**失败不阻断**。

## 已知会失效的地方（先写下来，不许假装没有）

- **C3 之后仍然待确认**：confess 对产出质量有没有正贡献，未测。它可能只是又一层仪式。
  这个设计的目的是"让 C3 可测"——有了独立通道和日志，才能做保留/剥离的对照。
- **自白可以被表演**：OpenAI 假设"真相比伪装更容易优化"，这个假设没有强证据。
  在这里同样成立：AI 可以学会写"看起来有证据、结构完整"的坦白而内容不实。
  缓解只有一条：要求写**具体到能复现的东西**（用例名、输出行、文件:符号），
  而不是"我核对过了"。这也只是提高造假成本，不是消除。
- **不进门的字段容易被绕过**：confess 文件不检查，意味着 AI 可以写一个空文件。
  接受。写成门就又回到自评有成本的老路。
- **只在 `done` 之后**，所以"AI 中途直接停住不回话"这种失效它看不见。
