# evidence-first 决定

- 级别：L2
- 原话（一字不改）：不是说 批评你 而是这块的流程 是能进行优化的 本来 开始前就能进行确认的事情 现在 要多次才有结果 我觉得这个不应该在开发的流程中出现 ，这块代价很大 需要进行优化工作；流程
- 我理解你要的是：把「本该动手前就能查清的事」写进流程强制点，避免来回试探——给方案前先查完能查的事实；查不到才标待确认，并说清卡在哪、下一步谁去查
- 可能理解错的地方：你可能还会要求「查证失败的兜底」也进流程（查了但没有权限/资料，怎么办），我按「说明卡点 + 给可执行下一步」处理，没有另立一档。另外你可能希望这条约束作用于所有外部工具调研，不只是 DSH 这类集成判断。
- 本质：现有 `scope.md` 有证据分级（已证实/推断/待确认/存在冲突），但只规定「结论怎么标」，没规定「给结论前该查多少」。缺的是查证义务。
- 怎样算满足：
  1. `scope.md` 有一条硬规则：能自己查的事实，给方案前必须先查完
  2. 该条给出可判定的边界：什么算「能自己查」（本机存在、命令可跑、文件可读）
  3. 查不到时输出格式固定：卡在哪 + 缺什么 + 谁去补
  4. 给出反例，说明本次踩的坑（先建议后查证，来回 4 轮）
  5. `AGENTS.md` 指路牌加一行指向它
- 未知：无
- 这次不做：不新加流程阶段、不改 `workflow_next` 的行为、不做自动查证工具。这是文档约束，靠 agent 遵守，不是机器门——因为「该不该查」无法机器判定。
- 现有能力：
  - `references/scope.md` 证据四类标记 —— 已证实
  - `references/scope.md` 有「先查卡片，再读域文件，再回代码」的查证顺序 —— 已证实
  - `templates/decision-template.md` 有「现有能力」要求带 `文件:符号` —— 已证实
- 旧决定：`specs/intent-confirm/decision.md`（理解确认回路）。实现是否仍符合：符合，本决定是它的补充——那个管「理解对不对」，本决定管「事实查没查」。
- 最小充分方案：
  1. `scope.md` 的「证据」章节前加「查证义务」小节
  2. 定三条边界：本机可读/可跑/可问的，必须查；查不到说明卡点；不许把查证当问题抛给用户
  3. 加一个本次反例（DSH 集成判断），形式与 `debt-gate.md` 的「不通过的样子」一致
  4. `AGENTS.md` 加一行
- 为什么更小的做法不够：
  - 只写在 `AGENTS.md` 指路牌里 → 那段是索引，不承载规则，读了也记不住边界
  - 只加一句「先查证」不给边界 → 「能自己查」没定义，遇到权限/网络问题仍会抛回给用户
  - 加到 `decision-template.md` → 模板只管产物形状，管不住「给建议前」这个时刻
- 相关的债：A 现在偿还——这是流程缺陷，每发生一次就多几轮往返，成本高于本次改动。
- 风险：不碰契约、持久化、权限、状态、回滚。
